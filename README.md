# Customer Shopping Behaviour Analysis

## 1. Project Overview

This project focuses on analysing customer shopping behaviour using retail transaction data from shopping malls in Istanbul, Turkey.

The main objective is to understand customer purchasing patterns, product category preferences, payment methods, age-group behaviour, gender-based shopping trends, and sales performance.

The project uses **Excel, MySQL, and Power BI** to clean, analyse, and visualise the dataset.

## 2. Project Objectives

- Analyse customer shopping behaviour.
- Identify popular product categories.
- Understand purchasing patterns by gender and age group.
- Identify the most commonly used payment method.
- Analyse revenue across different product categories.
- Compare shopping behaviour across shopping malls.
- Create an interactive Power BI dashboard.
- Generate useful business insights and recommendations.

### Sample SQL Queries

**1. Total Records**

```sql
SELECT COUNT(*) AS total_records
FROM customer_shopping_data;
```

**2. Total Quantity**

```sql
SELECT SUM(quantity) AS total_quantity
FROM customer_shopping_data;
```

**3. Payment Method Distribution**

```sql
SELECT
    payment_method,
    COUNT(*) AS total_transactions
FROM customer_shopping_data
GROUP BY payment_method
ORDER BY total_transactions DESC;
```

**4. Gender-wise Transactions**

```sql
SELECT
    gender,
    COUNT(*) AS total_transactions
FROM customer_shopping_data
GROUP BY gender;
```

**5. Category-wise Quantity**

```sql
SELECT
    category,
    SUM(quantity) AS total_quantity
FROM customer_shopping_data
GROUP BY category
ORDER BY total_quantity DESC;
```

**6. Shopping Mall Analysis**

```sql
SELECT
    shopping_mall,
    COUNT(*) AS total_transactions
FROM customer_shopping_data
GROUP BY shopping_mall
ORDER BY total_transactions DESC;
```

**Note:** Confirm the actual database and table names in MySQL Workbench before running these queries.

### Step 5: KPI Cards

The dashboard includes these key performance indicators:

- Total Revenue
- Total Quantity
- Total Customer Records

**DAX – Total Quantity**

```dax
Total Quantity =
SUM('customer_shopping_data'[quantity])
```

**DAX – Total Customer Records**

```dax
Total Customer Records =
DISTINCTCOUNT('customer_shopping_data'[customer_id])
```

**Important:** The dataset's customer ID appears to be assigned per transaction in this version. Therefore, 99,457 distinct IDs should not automatically be interpreted as 99,457 individual repeatable customers. Label this KPI carefully.

**Revenue calculation:** Validate whether `price` is already the transaction line amount or a unit price before calculating revenue. If it is already the line amount, use:

```dax
Total Revenue =
SUM('customer_shopping_data'[price])
```

If it is a genuine unit price, use:

```dax
Total Revenue =
SUMX(
    'customer_shopping_data',
    'customer_shopping_data'[quantity] *
    'customer_shopping_data'[price]
)
```

Do not use both calculations interchangeably. Confirm the meaning of `price` from the actual data before reporting a final revenue figure.
